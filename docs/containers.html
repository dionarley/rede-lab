Acesso aos containers

Como entrar no CT de cada instância do lab — isp, casa e servidor — usando Podman, Docker ou o wrapper de Compose.

$ podman exec -it isp bash

Comandos exibidos para Podman.

01

Visão geral

O Compose define container_name fixo. Por isso os nomes são sempre isp, casa e servidor, sem o prefixo do projeto.

Instâncias 3

ISP, casa e servidor, todos na bridge lab-net.

Nomes fixos

Definidos em docker-compose.yml via container_name.

Acesso root

O exec padrão entra como root; labuser só no servidor.

Conferir o status

status dos containers
podman ps --format 'table {{.Names}}\t{{.Status}}'
./scripts/compose.sh ps
Instância Container IP Função
ISP / NAT isp 10.0.0.1 Gateway, forwarding e MASQUERADE.
Casa casa 10.0.0.10 Cliente SSH e WireGuard (wg1).
Servidor servidor 10.0.0.20 sshd e servidor WireGuard (wg0).
Se um container não aparecer: veja todos com podman ps -a e inicie com podman start <nome>. Se ele foi removido, recrie com ./scripts/compose.sh up.
02

Entrar em cada CT

O comando é o mesmo para todos; muda apenas o nome do container. -it significa interativo + TTY.

shell interativo
podman exec -it isp bash
podman exec -it casa bash
podman exec -it servidor bash
Instância Comando Observação
ISP / NAT podman exec -it isp bash Use para inspecionar NAT e rotas.
Casa podman exec -it casa bash Use para testar SSH e WireGuard.
Servidor podman exec -it servidor bash Use para ver sshd, portas e wg0.
Comando único: omita o -it para rodar sem shell. Exemplo: podman exec casa ip route.
Bash ausente? Se a imagem não tiver bash, use podman exec -it isp sh.
Para sair: digite exit ou pressione Ctrl + D. Isso encerra apenas o shell do exec, não o container.
03

Por instância

Comandos prontos para entrar e inspecionar cada container.

isp 10.0.0.1

ISP / NAT

O roteador containerizado que aplica forwarding e MASQUERADE.

Entrar

podman exec -it isp bash

Inspecionar

ip -brief addr
ip route
iptables -t nat -L POSTROUTING -n -v
iptables -L FORWARD -n -v
casa 10.0.0.10

Casa

Cliente SSH e WireGuard. É daqui que saem os testes para o servidor.

Entrar

podman exec -it casa bash

Inspecionar

ip -brief addr
ip route
wg show
ssh labuser@10.0.99.1
servidor 10.0.0.20

Servidor

Executa o sshd e o endpoint WireGuard na porta 51820/udp.

Entrar

podman exec -it servidor bash

Inspecionar

ip -brief addr
ip route
wg show
ss -lntp
04

Via Compose

Se o lab foi criado com ./scripts/compose.sh up, use o wrapper para executar comandos sem se preocupar com o engine.

compose.sh exec
./scripts/compose.sh exec isp bash
./scripts/compose.sh exec casa bash
./scripts/compose.sh exec servidor bash
Vantagem: o wrapper detecta podman-compose, podman compose ou docker compose automaticamente.
Comando único: ./scripts/compose.sh exec casa wg show.
Cenário Comando
Container já em execução podman exec -it <container> bash
Lab criado via Compose ./scripts/compose.sh exec <container> bash
Usando Docker docker exec -it <container> bash
Não misture: se o container foi criado pelo Compose, o podman exec continua funcionando, mas o caminho consistente é ./scripts/compose.sh exec. O wrapper também funciona para ps, logs, start e stop.
05

Entrar como labuser

Por padrão, o exec entra como root. No servidor, o usuário labuser existe e pode ser usado explicitamente.

usuário não-root
podman exec -it --user labuser servidor bash
podman exec --user labuser servidor id
podman exec --user labuser servidor sh -c 'whoami; pwd'
Onde existe: apenas no container servidor, criado no servidor/Dockerfile com shell /bin/bash.
Onde não existe: na casa e no isp. Use o usuário padrão (root) ou crie o usuário se precisar.
Não confunda: ssh labuser@10.0.99.1 entra pelo sshd, com autenticação e sessão SSH. podman exec --user labuser executa um processo diretamente no container, sem passar pelo sshd.
06

Inspeção rápida

Comandos de uma linha para checar o estado de cada parte do lab.

Quero ver Comando
IPs da casa podman exec casa ip -brief addr
Rotas da casa podman exec casa ip route
WireGuard da casa podman exec casa wg show
Portas abertas no servidor podman exec servidor ss -lntp
NAT do ISP podman exec isp iptables -t nat -L POSTROUTING -n -v
Logs do servidor podman logs -f servidor
Dica: para comandos únicos, não use -it. Isso evita o erro de TTY ao rodar dentro de scripts, CI ou pipes.
07

Iniciar, parar e ver logs

Se o container estiver parado, o exec falha. Inicie antes de entrar.

Engine direto

ciclo de vida
podman ps -a
podman start isp
podman stop isp
podman restart isp
podman logs -f isp

Compose

compose.sh
./scripts/compose.sh start
./scripts/compose.sh stop
./scripts/compose.sh restart
./scripts/compose.sh logs servidor
Container removido: podman start não recria um container que não existe. Nesse caso, use ./scripts/compose.sh up ou ./scripts/deploy.sh.
08

E a “instância” da VPN?

A VPN não é um container separado. São interfaces dentro da casa e do servidor.

inspecionar a VPN
./scripts/vpn.sh status
podman exec casa wg show
podman exec servidor wg show
Como funciona: a casa tem wg1 em 10.0.99.10; o servidor tem wg0 em 10.0.99.1:51820/udp. Para “entrar na VPN”, entre no CT da casa ou do servidor e rode wg show.

Detalhes em docs/wireguard.md e docs/vpn-operacao.md.

09

Troubleshooting

Problemas comuns ao entrar nos containers.

“no such container: isp”

O container não existe ou está parado. Veja todos e inicie:

podman ps -a
podman start isp

Se ele foi removido, recrie o lab com ./scripts/compose.sh up.

“exec: bash: executable file not found in $PATH”

A imagem não tem bash. Use sh:

podman exec -it isp sh
“the input device is not a TTY”

O -it exige um terminal interativo. Em scripts, CI ou pipes, remova o -t (ou ambos):

podman exec casa ip route
podman exec -i casa sh -c 'cat /etc/os-release'
“permission denied” ao usar --user labuser

O usuário existe apenas no container servidor. Confirme com:

podman exec servidor id labuser

Na casa e no isp, use o usuário padrão (root).

“nenhum Compose encontrado” no compose.sh

Instale podman-compose ou docker compose, ou force o binário no .env:

COMPOSE_BIN=podman-compose
# ou
COMPOSE_BIN=docker compose
10

Referência rápida

Cheat sheet para copiar e colar.

cheat sheet
# entrar
podman exec -it isp bash
podman exec -it casa bash
podman exec -it servidor bash

# comando único
podman exec isp ip route
podman exec casa wg show
podman exec servidor ss -lntp

# status e logs
podman ps
podman logs -f servidor
podman start casa

# compose
./scripts/compose.sh exec casa bash
./scripts/compose.sh ps

# labuser (somente servidor)
podman exec -it --user labuser servidor bash
Resumo: para o dia a dia, use ./scripts/compose.sh exec <container> bash se o lab foi criado via Compose, ou podman exec -it <container> bash se estiver usando o engine diretamente.
